Mathematics reels are clean, precise and constructed live in front of the viewer, in the style of a good maths board: dark navy, light-blue curves, one amber point, restrained.
- Use the `maths_navy` look and the `maths` layout with a 3-line `header`. Build graphs with the `cartesian` prefab (axes through the origin, unit ticks, curves that draw themselves, a moving point with drop lines, an optional permanent highlighted point). Use `value_table` for tables of values, filled column by column as each value is spoken. Use `formula` and `derivation` cards for equations and algebra; with a card at the `top` anchor, shift the camera `target.y` and `position.y` up by about 0.9 so the graph sits below the card.
- Construct the idea in the order a teacher would: define the function, choose x values, compute y, plot the points, let the curve draw, then name what matters (vertex, intercepts, symmetry, slope, direction of opening).
- Every number shown must be computed from the function stated in the narration: recompute each y from x yourself before you write it. A table cell, a label and the curve must agree exactly. Never show a rounded value as exact.
- Show change by animating the equation itself: put an expression of `t` (for example `mix(1,-1,smooth(0.6,3.2,t))*X^2`) inside the curve so a coefficient, shift or parameter moves while the viewer watches. Choose `ymin` and `ymax` so the curve stays in view for the whole animation; a curve leaving the plot is cut at the edge.
- Pick `xmin`, `xmax`, `ymin`, `ymax` as integers with `nx = xmax-xmin+1` and `ny = ymax-ymin+1` ticks (at most 13 each); plot width and height 3.0 to 3.4 with the camera at distance 8 to 9.
- The `mascot_m` prop may appear in a bottom corner (never over the graph or a card) for continuity; it carries no information. Use at most one `pop` word per scene for the key term, and one `sticker` for the single rule to remember.
- Keep it restrained: few objects, high contrast, no decoration. One curve, one highlighted point and one formula at a time is better than a busy scene.
- `cartesian` draws y = X^2 by default: set `s1` to 0 or give your own `y1` whenever the beat is about a different curve. For a curve opening sideways give `x1` (for example `X^2/8`) and `y1` `X` with `smin`/`smax` set to ymin/ymax.
- For the focus and directrix of a parabola, for locus definitions and for eccentricity topics, ALWAYS use the `parabola_focus` prefab: it computes the focus, directrix, the moving point P, its foot M and the segments PF and PM from one number `p` (set `orient` 1 for a parabola opening to the right, as in y^2 = 4ax), so PF equals PM exactly in the picture. Never place a focus, a directrix or a distance segment by hand: if the curve is y = x^2/(4p), the focus is (0, p) and the directrix is y = -p, and a hand-placed one is almost always wrong.
- Header lines must be short: a section tag, a headline of at most 28 characters and a subtitle of at most 40 characters.
- A worked example in the narration (a point, a distance, a value) must be consistent with the figure: if the narration says the focus is (2, 0), the figure has p = 2 and orient 1, and the point P you name must lie on that curve (for y^2 = 8x the point (2, 4) does, (4, 4) does not).
